# ORBIT | أوربت

غرفة عمليات عربية خاصة لمراقبة أسطول البرامج بأدلة قابلة للتتبع، من دون تعديل المستودعات المراقبة أو دمج أو نشر تغييرات عليها.

## ما يعمل فعليًا

- صفحة واحدة: لكل برنامج سطر واحد (اسمه وحالته)، وأي مشكلة فيها زر «انسخ» يجهّز تقريرًا كاملًا تلصقه حيث تشاء (كلود أو غيره).
- زر أعلى الصفحة ينسخ كل المشاكل دفعة واحدة.
- دخول خاص بخادم ORBIT عبر `ORBIT_OPERATOR_PASSKEY` وجلسة HTTP-only.
- قراءة GitHub (المستودعات وعمليات Actions وآخر تعديل) بصلاحية قراءة فقط، مع فحص رابط الموقع.
- عند فتح الصفحة يُجرى الربط تلقائيًا إن لم يُتحقق من البرامج أو كانت بياناتها أقدم من 6 ساعات، وإن تعذر الربط يُكتب السبب تحت البرنامج.
- إضافة برنامج بالاسم والرابط فقط، وإزالة ما أضفته.
- استقبال أحداث حساسات مصادق عليها ومقيدة لكل برنامج مع تنقية البيانات (واجهة برمجية فقط).
- **زائر آلي بمتصفح حقيقي** كل يوم: يفتح كل موقع على سطح المكتب وعلى جوال وعلى جوال باتصال ضعيف، ويتبع بضع صفحات داخلية، ويفحص: أخطاء JavaScript، صفحة فارغة، تجاوز عرض الجوال، صور مكسورة، نصوص منسية (`Lorem ipsum`، `undefined`، `NaN`)، اتجاه RTL، أسماء الأزرار لقارئ الشاشة، رؤوس الأمان، مفاتيح مسرّبة في الملفات، وتغيّر شكل الصفحة الرئيسية عن الأمس.
- **إنذار مبكر قبل العطل**: يتعلم أوربت سرعة كل موقع وحجم صفحته المعتادين وينبّه عند التباطؤ المستمر، ويفحص شهادة HTTPS ويحذّر قبل 14 يومًا من انتهائها.
- **تقرير يكفي كلود لإصلاح الخطأ**: يشمل السبب الجذري المحتمل، وآخر تعديل سبق بداية المشكلة، وما فعله الزائر قبل الخطأ وموضعه في الكود (إن رُكّب الحساس).
- **زر «اشرح»** على كل برنامج: الخطورة وماذا يحدث للزائر وأول خطوة، بـ Gemini إن ضُبط المفتاح وبقواعد ثابتة إن لم يُضبط.
- **زائر ذكي بـ Gemini** (اختياري): يلعب دور مستخدم كويتي فضولي على الموقع، فيتصفح ويجرّب الأزرار والحقول، ويسجّل الدخول بحساب اختبار مخصص إن وُجد. الكود (وليس النموذج) هو من يقرر ما يُسمح به: لا حذف ولا دفع ولا تسجيل خروج ولا كتابة في كلمات السر ولا مغادرة الموقع، والكتابة في البيانات مغلقة افتراضيًا. الأخطاء التي رآها المتصفح بنفسه تُسجَّل مشاكل مع الحركة التي سبقتها («بعد الضغط على حفظ: خطأ…»)، وملاحظات النموذج تُسجَّل تحذيرات فقط لأنه قد يخطئ.
- **انتهاء النطاق وتوكن GitHub**: فحص تاريخ انتهاء اسم النطاق (RDAP) أسبوعيًا مع تحذير قبل 30 يومًا، وتنبيه أعلى الصفحة قبل 14 يومًا من انتهاء توكن GitHub الذي يقرأ به أوربت. النطاقات على منصات الاستضافة (`web.app` وغيرها) لا تُفحص لأنك لا تجدّدها، وبعض السجلات (مثل `.kw`) لا تدعم RDAP فتبقى «غير معروف» بلا تحذير كاذب.
- **مراقبة المراقِب**: إن صمتت المراقبة التلقائية أكثر من 90 دقيقة يظهر تنبيه أعلى الصفحة، ويمكن ربط `ORBIT_HEARTBEAT_URL` بخدمة خارجية تنبّهك على جوالك إن توقفت.
- **ضجيج أقل من الزوّار**: خطأ برمجي رآه زائر واحد فقط يظهر «ملاحظة» في تقرير النسخ ولا يجعل البرنامج أحمر، وقد يكون إضافة متصفح أو ذاكرة قديمة؛ ويصير مشكلة إن رآه زائران. فشل الاتصال بطلب معيّن لا يُعدّ عطلًا إلا إن حدث لثلاثة زوّار خلال ساعة. وأي بلاغ قديم يزول بعد 6 ساعات من آخر مرة رُئي فيها، حتى لو أرسل زوّار آخرون بلاغات أخرى. والزائر الخفيف يعيد طلبه مرة واحدة إن لم يُجَب أو جاء 5xx قبل أن يعدّه فشلًا.
- **سجلات الخادم**: يقرأ أوربت أخطاء `ERROR` من سجلات Cloud Run لكل برنامج تُعرّفه في `ORBIT_LOG_SOURCES` (مثال: `ORDER=مشروعي/order-api;ADMIN=مشروعي/admin-api`)، ويحتاج حساب تشغيل أوربت دور «Logs Viewer» فقط. الخطأ الواحد المتكرر 3 مرات في نصف ساعة مشكلة، وأقل من ذلك تحذير. إن تعذرت القراءة يظهر تحذير بدل أن يُظن أن لا أخطاء. وإن مُنح الحساب أيضًا دور «Cloud Run Viewer» عرف أوربت أي نسخة تخدم الزوار: خطأ نسخة لا تخدم أحدًا (نشر جديد فشل) تحذير أصفر، أما خطأ النسخة الحية فيبقى أحمر. بدون هذا الدور تُعامَل كل الأخطاء كأنها من نسخة حية.
- **اختبار الحساس الذاتي**: الزائر اليومي يجعل صفحة الموقع تُطلق خطأً تجريبيًا عبر الحساس نفسه (`ORBIT-SELFTEST`) ويتأكد أنه وصل. لا يصير مشكلة أبدًا، لكنه يكشف حساسًا غير مركّب أو سياسة CSP تحجبه.
- **مقارنة الأداء بعد النشر**: يحفظ أوربت سرعة الموقع قبل آخر commit، ويحذّر باسم الـ commit إن صار أبطأ بعده.
- **التقرير الأسبوعي**: كل اثنين يصل ملخص على الجوال (ما حدث، ما يتكرر، ما يقترب موعده)، وزر «تقرير الأسبوع» في الصفحة ينسخ نصه الكامل.
- **رابط الـ commit**: إن بدأت مشكلة بعد آخر تعديل يظهر في التقرير رقمه ورابطه على GitHub.
- PWA وRTL ووضعان فاتح وداكن حسب جهازك.

لا يعني نجاح GitHub أو غياب الحوادث أن الموقع الإنتاجي سليم. «يعمل» تعني أن GitHub مربوط وأن الموقع استجاب ولا يوجد فحص فاشل؛ رحلة المستخدم الكاملة لا تُختبر.

## التشغيل المحلي

```bash
cp .env.example .env
npm ci
npm run dev
```

يجب إعداد `ORBIT_OPERATOR_PASSKEY` بقيمة عشوائية لا تقل عن 16 محرفًا. لا تضع مفاتيح الحساس أو GitHub أو Gemini في متغيرات Vite أو كود المتصفح.

## التحقق

```bash
npm run check
ORBIT_OPERATOR_PASSKEY="<test-passkey>" PORT=3100 npm run dev
```

ثم في طرفية أخرى:

```bash
ORBIT_OPERATOR_PASSKEY="<test-passkey>" node scripts/visual-smoke.mjs
```

## تشغيل الزائر الذكي

1. أضف سر GitHub Actions باسم `GEMINI_API_KEY`.
2. أنشئ **حساب اختبار مخصصًا** في كل موقع يحتاج دخولًا (لا تستخدم حسابك الشخصي)، بصلاحيات محدودة وبلا بيانات حقيقية، ثم أضف السر `ORBIT_TEST_LOGINS` بهذا الشكل (المفتاح هو الاسم الرمزي للبرنامج في أوربت):
   `{"NAHJ":{"email":"orbit-test@example.com","password":"..."}}`
3. متغيرات اختيارية: `ORBIT_AI_EXPLORE=0` لإيقافه، `ORBIT_AI_MAX_CALLS` (الافتراضي 40 استدعاءً للتشغيلة كلها)، `ORBIT_AI_ALLOW_WRITES=1` للسماح بالحفظ والإرسال (على حساب اختبار فقط).

الدخول بزر «Google» غير مدعوم، لأن Google يمنع الأتمتة غالبًا.

## تركيب حساس المتصفح (اختياري، لكل موقع بموافقتك)

أضف هذا السطر قبل `</body>` في الموقع المراقَب. بدونه لا يرى أوربت ما يحدث للمستخدمين أثناء الاستخدام، بل ما يراه الزائر الآلي فقط. لا يُرسل الحساس نصًا كتبه المستخدم ولا روابط بمعاملاتها:

```html
<script src="https://orbitq8.web.app/orbit-sensor.js" async></script>
```

يُبلَّغ عن خطأ برمجي من كود الموقع نفسه من أول زائر، وعن غيره عند زائرَين مختلفين. ذاكرة التجميع تُمسح مع إعادة تشغيل الخادم، فالنتائج تُحفظ على سجل البرنامج 6 ساعات.

## حدود صريحة

- الزائر الذكي لا يعمل قبل ضبط `GEMINI_API_KEY`، ولا يدخل المواقع التي تتطلب حسابًا قبل ضبط `ORBIT_TEST_LOGINS`. مفتاح Gemini وتوكنات الخدمات الأخرى لا تُفحص تواريخ انتهائها.

- أوربت يقرأ ويقترح فقط؛ لا يعدّل البرامج المراقبة ولا يدمج ولا ينشر عنها.
- لا تُركب الحساسات في البرامج المراقبة دون موافقة مستقلة.
- النشر الإنتاجي يدوي من GitHub Actions (**Deploy ORBIT production**) ويُوثَّق في [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).
