# ORBIT | أوربت

غرفة عمليات عربية خاصة لمراقبة أسطول البرامج بأدلة قابلة للتتبع، من دون تعديل المستودعات المراقبة أو دمج أو نشر تغييرات عليها.

## ما يعمل فعليًا

- صفحة واحدة: لكل برنامج سطر واحد (اسمه وحالته)، وأي مشكلة فيها زر «انسخ لكلود» يجهّز تقريرًا كاملًا تلصقه في كلود.
- زر أعلى الصفحة ينسخ كل المشاكل دفعة واحدة.
- دخول خاص بخادم ORBIT عبر `ORBIT_OPERATOR_PASSKEY` وجلسة HTTP-only.
- قراءة GitHub (المستودعات وعمليات Actions وآخر تعديل) بصلاحية قراءة فقط، مع فحص رابط الموقع.
- عند فتح الصفحة يُجرى الربط تلقائيًا إن لم يُتحقق من البرامج أو كانت بياناتها أقدم من 6 ساعات، وإن تعذر الربط يُكتب السبب تحت البرنامج.
- إضافة برنامج بالاسم والرابط فقط، وإزالة ما أضفته.
- استقبال أحداث حساسات مصادق عليها ومقيدة لكل برنامج مع تنقية البيانات (واجهة برمجية فقط).
- PWA وRTL ووضعان فاتح وداكن حسب جهازك.

لا يعني نجاح GitHub أو غياب الحوادث أن الموقع الإنتاجي سليم. «يعمل» تعني أن GitHub مربوط وأن الموقع استجاب ولا يوجد فحص فاشل؛ رحلة المستخدم الكاملة لا تُختبر.

## التشغيل المحلي

```bash
cp .env.example .env
npm ci
npm run dev
```

يجب إعداد `ORBIT_OPERATOR_PASSKEY` بقيمة عشوائية لا تقل عن 16 محرفًا. لا تضع مفاتيح الحساس أو GitHub أو Gemini في متغيرات Vite أو كود المتصفح.

## التحقق

```bash
npm run check
ORBIT_OPERATOR_PASSKEY="<test-passkey>" PORT=3100 npm run dev
```

ثم في طرفية أخرى:

```bash
ORBIT_OPERATOR_PASSKEY="<test-passkey>" node scripts/visual-smoke.mjs
```

## حدود صريحة

- أوربت يقرأ ويقترح فقط؛ لا يعدّل البرامج المراقبة ولا يدمج ولا ينشر عنها.
- لا تُركب الحساسات في البرامج المراقبة دون موافقة مستقلة.
- النشر الإنتاجي يدوي من GitHub Actions (**Deploy ORBIT production**) ويُوثَّق في [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).
