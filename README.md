# ORBIT | أوربت

غرفة عمليات عربية خاصة لمراقبة أسطول البرامج بأدلة قابلة للتتبع، من دون تعديل المستودعات المراقبة أو دمج أو نشر تغييرات عليها.

## ما يعمل فعليًا

- دخول خاص بخادم ORBIT عبر `ORBIT_OPERATOR_PASSKEY` وجلسة HTTP-only.
- قراءة GitHub والمستودعات وعمليات Actions والـcommits بصلاحية قراءة فقط.
- استقبال أحداث حساسات مصادق عليها ومقيدة لكل برنامج، مع تنقية البيانات وتجميع التكرار.
- تحديث لحظي عبر SSE، ودورة حياة للحوادث، ومهمة إصلاح قابلة للنسخ.
- إدارة ديناميكية للأسطول: إضافة، تحقق، إيقاف، أرشفة، إعادة تفعيل وفك ربط.
- محاكاة Canary وDigital Twin آمنة، وذاكرة هندسية لا تقبل السبب الجذري غير المؤكد.
- PWA وRTL ووضعان فاتح وداكن وتجربة متجاوبة.

لا يعني نجاح GitHub أو غياب الحوادث أن الموقع الإنتاجي سليم. تعرض الواجهة مصدر الدليل وحالته: `Live` أو `Cached` أو `Demo` أو `Unavailable` أو `Not Configured`.

## التشغيل المحلي

```bash
cp .env.example .env
npm ci
npm run dev
```

يجب إعداد `ORBIT_OPERATOR_PASSKEY` بقيمة عشوائية لا تقل عن 16 محرفًا. لا تضع مفاتيح الحساس أو GitHub أو Gemini في متغيرات Vite أو كود المتصفح.

## التحقق

```bash
npm run check
ORBIT_OPERATOR_PASSKEY="<test-passkey>" PORT=3100 npm run dev
```

ثم في طرفية أخرى:

```bash
ORBIT_OPERATOR_PASSKEY="<test-passkey>" node scripts/visual-smoke.mjs
```

## حدود صريحة

- لا يوجد في المستودع مسار نشر إنتاجي أو رابط إنتاج موثق حتى الآن.
- لا تُركب الحساسات في البرامج المراقبة دون موافقة مستقلة.
- تشخيص Gemini اختياري وعند الطلب؛ المحرك الحتمي هو الافتراضي.
- اللقطات السحابية تخص تجربة المشغل ولا تستبدل حالة الخادم المشتركة.
